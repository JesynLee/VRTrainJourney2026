## 1. 项目主题

本项目利用 VR 技术为老年用户构建沉浸式“火车旅行体验”。用户佩戴 VR 设备后，将置身于一节位于列车前端二层的全景观光车厢内，以第一人称坐姿视角，通过正前方观景大窗欣赏依次展开的三段主题旅程。

核心设计理念：以内容体验、情绪流动、清晰的旅程引导和舒适的前向观看视角为中心，而不是复杂的交互操作。由于最终成果以 demo 演示为主，项目不制作复杂首页动画或完整菜单系统，但保留必要的 VR 手柄控制，用于开始体验、重新居中、暂停继续和跳转到下一站。

本项目此前使用旧版本 Unity 引擎进行开发。由于旧版本难以配合最新 AI 内容生成与相关工作流，项目已升级至新版 Unity LTS。旧项目在新引擎中打开后虽然没有明显报错，但出现了材质异常等潜在兼容问题。为了避免后续开发中持续受到旧项目资源和设置残留的影响，当前策略调整为：废弃旧项目，在新版 Unity LTS 中重新创建项目，并按照本企划书重新搭建场景、材质、视频、音频和基础脚本系统。技术栈上不再沿用 Built-in Render Pipeline，而是采用 Unity 6 官方更推荐的新项目方向：URP + OpenXR + XR Interaction Toolkit。

## 2. 设计哲学：用 VR 弥补身体的局限

老年用户因身体条件限制，许多真实存在于地球上的壮丽景观可能终其一生无法亲临。本项目的设计核心不是单纯的怀旧回忆，而是：

> 让老年用户看到这个世界真实存在、但他们无法亲身抵达的地方，并在最后给予一段超越现实但安全平静的精神安抚。

### Mentoring 反馈的设计转化

在课程合作老年人福利中心的 mentoring 中，机构人员提出了一个核心反馈：老年用户在体验过程中需要明确知道自己当前处于哪一站、正在进入哪一段旅程。也就是说，项目不能只是连续播放三段风景视频，而需要通过“到站提示”和“段落过渡”让用户理解画面变化的原因。

因此，本项目将原本的三段主题视频重新组织为“三个车站”的旅行结构，并在每段之间加入语音提示和柔和过渡。该设计用于增强视频之间的承接性，避免用户产生“画面突然变化但不知道发生了什么”的困惑。

| Mentoring 建议 | 在本项目中的体现 |
|---|---|
| 老年人需要知道自己当前所在位置 | 三段视频设计为三个车站，并加入到站语音提示 |
| 视频之间需要有承接性 | 每段之间加入淡入淡出、短暂停顿和语音提示 |
| 老年人偏好简单内容，不喜欢复杂操作 | 全程以观看和聆听为主，降低交互负担 |
| 喜欢熟悉、舒适的氛围 | 第一站以怀旧场景开场，建立情绪安全感 |
| 画面变化不宜过快 | 单段控制在约 45 秒，采用缓慢自然的过渡 |
| 需要稳定感 | 使用固定坐姿视角和前向观景窗，降低晕动风险 |

## 3. 三站式主题内容设计

### 整体叙事弧线

```text
金色乡村站 → 峡湾观景站 → 极光花田站
熟悉、温暖 → 真实、震撼 → 超越、平静
情感唤醒   → 认知扩展   → 精神安抚
```

情绪流动为：温暖开场、震撼中段、平静收尾。这样的节奏适合老年用户的感官承受能力，也能让体验从现实感逐渐过渡到精神性的安抚。

### 第一站：金色乡村站

**主题：金色午后的欧洲乡村小站**

这是一个不绑定任何特定文化记忆，却能让多数用户感到“似曾相识”的场景。

**具体画面：**
列车缓缓驶过法国或意大利南部的乡村腹地。午后三四点的阳光把一切染成暖金色。石砌的小站台、窗台上的天竺葵花箱、穿围裙的老妇人向车厢挥手、远处麦田随风起伏，偶尔有一棵橄榄树伫立在田间。

**选择理由：**

- 欧洲乡村是跨文化的怀旧符号，不强行绑定某一国家或某一代人的具体记忆。
- 暖金色调、低速移动和友善人物动作共同营造安全、被欢迎的感受。
- AI 生成欧洲乡村场景的可控性较高，适合作为第一站内容。

### 第二站：峡湾观景站

**主题：挪威峡湾的列车穿行**

这是一个真实存在于地球上，但需要体力、时间和长途跋涉才能抵达的地方。

**具体画面：**
列车沿悬崖铁路穿行，两侧是壁立千仞的深绿峡湾，雪山融水形成的瀑布从高处直落入湾中，冰川蓝的海水在山谷中平静流淌。列车偶尔穿过短暂的隧道，再钻出来时，一个新的峡湾铺展在眼前。

**选择理由：**

- 挪威峡湾铁路有现实原型，“坐火车看峡湾”的叙事自然成立。
- 震撼感来自尺度对比，而不是速度、旋转或混乱画面。
- 峡湾、瀑布和雪山属于 AI 视频生成中相对稳定的自然场景。

### 第三站：极光花田站

**主题：极光之下的千年花田**

这是一个基于真实自然现象，但在现实中几乎不可能同时出现的“完美瞬间”。

**具体画面：**
黄昏将至，天空还留有橙紫色余光。北极光从地平线开始慢慢蔓延，绿色和淡紫色的光帷在苍穹中轻柔流动。列车穿行在一片无边际的花田之中，白色、粉色和淡蓝色的野花随微风摇曳。花田与极光之间仿佛连接着另一个世界，但整体氛围保持静谧、温暖和安全。

**选择理由：**

- 极光和花田都是真实自然现象，组合后形成“不真实但不违和”的仙境感。
- 场景中不加入机械、未来科技或恐怖元素，避免老年用户产生排斥。
- 作为最后一站，它能把体验从现实观光带向安静、超越日常的情感落点。

### 三站内容汇总

| 项目 | 第一站 | 第二站 | 第三站 |
|---|---|---|---|
| 站名 | 金色乡村站 | 峡湾观景站 | 极光花田站 |
| 主题 | 欧洲乡村小站 | 挪威峡湾铁路 | 极光花田 |
| 类型 | 怀旧 | 世界奇观 | 乌托邦仙境 |
| 时段 | 午后暖阳 | 晴天白日 | 黄昏入夜 |
| 单段时长 | 约 45 秒 | 约 45 秒 | 约 45 秒 |
| 主色调 | 暖金、麦黄、砖红 | 峡湾蓝、翠绿、雪白 | 极光绿、淡紫、花白粉 |
| 情绪 | 温暖、熟悉 | 震撼、开阔 | 超脱、平静 |
| 制作重点 | 稳定开场和情绪引导 | 尺度感和自然奇观 | 光色流动和精神安抚 |

## 4. 站点提示与过渡设计

### 4.1 设计目的

站点提示系统来自 mentoring 反馈，是本项目的重要体验决策。它的目的不是增加复杂交互，而是让老年用户在观看过程中始终知道自己处于哪一段旅程，从而减少困惑，提高安全感和沉浸感。

### 4.2 基本播放结构

```text
开场提示
↓
第一站视频：金色乡村站
↓
到站语音提示 + 画面淡出淡入
↓
第二站视频：峡湾观景站
↓
到站语音提示 + 画面淡出淡入
↓
第三站视频：极光花田站
↓
终点语音提示 + 体验结束
```

### 4.3 语音提示内容

正式项目中语音提示计划使用韩语，以符合课程环境和实际体验对象。项目计划书中先使用中文描述语义内容。

| 时机 | 语音提示语义 |
|---|---|
| 开场 | 本次列车即将出发，请放松坐好。 |
| 第一站开始 | 下一站，金色乡村站。 |
| 第一站结束 | 金色乡村站到了。接下来前往峡湾观景站。 |
| 第二站结束 | 峡湾观景站到了。接下来前往极光花田站。 |
| 第三站结束 | 极光花田站到了。本次旅程即将结束，请慢慢休息。 |

### 4.4 过渡方式

每段视频之间不直接切换，而是使用简单稳定的过渡：

- 当前视频和 BGM 逐渐淡出。
- 画面短暂进入柔和黑场或暗场。
- 播放到站语音提示。
- 下一段视频和音频逐渐淡入。

这种方式实现简单，适合课程项目周期，也能有效增强段落之间的承接性。

## 5. 载体设计：前向二层全景观光车厢

### 5.1 视角设计的核心决策

本项目采用“列车前进方向”的观景视角，而不是传统侧窗观景视角。这个决策来自上一版开发中的关键经验：如果用户主要观看侧窗风景，画面会更容易产生横向移动感，老年用户也更容易感到不稳定。相比之下，正前方视角更接近开车时通过前挡风玻璃看路的经验，视觉运动方向明确，风景从远处向近处推进，用户更容易理解列车正在前进。

因此，本项目的核心观看逻辑是：用户坐在列车最前端的二层观景车厢中，看向正前方的大窗。窗外视频需要呈现铁路、远景和沿途风景由远及近的推进感，而不是只呈现侧面掠过的风景。

### 5.2 二层前端车厢的设定理由

真实观景列车通常也会通过侧窗欣赏风景，因此这些列车不能直接作为 AI 视频生成时的画面参考。但它们仍然提供了重要的设计灵感：观光列车可以拥有更开阔、更高的位置和更强的旅行仪式感。

本项目将用户位置设定在列车前端二层，主要理由如下：

- 二层视角更高，能强化观景感，也能让远景更清楚。
- 前端视角能提供明确的前进方向，符合“列车旅行”的主题。
- 二层前端可以避开一层驾驶室、控制台和机械设备等复杂元素。
- 用户不需要操作列车，只需要以乘客身份坐在观景空间中观看旅程。
- 该设定兼顾了“像前窗驾驶视角一样清楚”和“不让用户真的处在驾驶室里”的体验需求。

### 5.3 关于铁轨和列车元素的生成策略

上一版企划中曾提出通过窗户底沿或视角控制，让铁轨、车头和车体结构不出现在主要视野中。这个方案在前向列车视角下并不合理，因为只要列车向前行驶，正前方就必然会出现向远处延伸的铁轨。

因此，本项目调整策略：AI 视频允许生成铁轨和必要的列车前向运动元素。需要重点避免的不是铁轨本身，而是以下内容：

- 过于复杂的驾驶室、控制台和仪表盘。
- 容易变形的近距离车头结构。
- 大量机械零件、按钮和操作设备。
- 过强的速度感、急转弯或剧烈晃动。

视频生成时应强调“稳定、缓慢、前向推进”的观景体验。铁轨可以作为方向感和列车主题的辅助元素存在，但画面重点仍然是远处逐渐接近的风景、站点和自然景观。

### 5.4 与真实观光列车的关系

Glacier Express、Rocky Mountaineer、Bernina Express、Flåm Railway 等真实观光列车可以作为氛围和概念参考，但不作为 AI 视频生成的直接画面模板。原因是现实观光列车通常依赖侧窗或大面积车窗观景，而本项目为了 VR 舒适度和叙事清晰性，选择了更明确的正前方视角。

这些真实案例在本项目中的参考价值主要体现在：

- 证明“列车本身可以作为观景旅行载体”。
- 提供复古、舒适、慢旅行的氛围方向。
- 支持二层或高视角观景空间的设计合理性。
- 帮助确定车厢应当是乘客空间，而不是驾驶空间。

### 5.5 车厢内饰与资源策略

车厢内饰是增强沉浸感的重要部分，但不是当前阶段的最高优先级。由于适合本项目的列车内饰 Assets 较难寻找，目前已有的可用资源主要是座椅模型。因此，本项目优先采用“基础几何体搭建 + 简单材质调整 + 后期逐步优化”的策略。

在首要完成度开发阶段，可以使用 Unity 中的 Cube、Plane 等基础几何体搭建地板、墙体、窗框、二层观景空间和简单家具，再通过材质颜色、木纹贴图、金属色和灯光调整建立基本氛围。如果 Unity AI 能辅助生成或搭建这些基础结构，则优先用于提高开发效率，而不是一开始追求复杂高精度车厢资产。

内饰开发优先级如下：

| 元素 | 当前策略 |
|---|---|
| 前方大窗与窗框 | 最高优先级，用于确立前向观景视角和视频边界 |
| 二层观景空间 | 最高优先级，用基础几何体明确用户所在位置 |
| 座椅 | 使用现有座椅 Assets，先保证坐姿视角成立 |
| 地板和侧墙 | 使用基础几何体和简单材质完成 |
| 简单桌面或扶手 | 有时间时添加，用于增强乘客空间感 |
| 复古灯具、窗帘、装饰画 | 后期优化内容，不作为核心完成条件 |
| 高质量整体车厢 Assets | 如果能找到合适资源再替换，否则不强求 |

### 5.6 当前阶段的完成标准

当前阶段不以复杂车厢建模作为主要目标，而是优先确保以下内容成立：

1. 用户视角明确位于列车前端二层。
2. 用户主要观看正前方风景，而不是侧窗风景。
3. 窗外视频具有从远处向近处推进的列车运动感。
4. 铁轨可以出现在视频中，并作为方向感元素存在。
5. 车厢内部使用基础模型和简单材质即可，只要能支撑沉浸式乘坐感。
6. 后期如果时间允许，再逐步优化车厢风格、装饰细节和高质量模型。

## 6. 视频、音频与脚本流程

### 6.1 视频制作流程

```text
确定三站主题与画面描述
↓
使用 Seedance 2.0 生成 AI 视频素材
↓
为每站撰写详细 prompt 并生成多个候选片段
↓
使用 DaVinci Resolve 挑选、剪辑并处理段间过渡素材
↓
导入 Unity，通过 VideoPlayer 组件播放
```

**视频规格：**

- 单站时长：约 45 秒。
- 全程总时长：约 2 至 3 分钟。
- 格式：MP4。
- 分辨率：根据 Meta Quest 2 的显示能力和性能预算进行优化。

**视频源策略：**
不预先锁定单一 AI 模型。正式制作阶段根据当时的生成质量、稳定性和可控性选择最合适的工具，候选包括 Seedance 等 AI 视频模型。视频生成 prompt 应明确要求正前方列车视角、二层观景高度、风景从远处向近处推进，并允许画面中出现稳定延伸的铁轨。

### 6.2 音频制作流程

```text
语音提示层：开场、到站、下一站和终点提示
↓
BGM 层：根据三站主题分别定制，优先级低于语音提示
↓
音量统一、淡入淡出和段间过渡处理
↓
导入 Unity，通过 AudioSource 组件分层播放
```

BGM 目前保留为增强沉浸感的辅助元素，但其必要性仍可根据制作时间和测试反馈调整。项目优先级为：视频播放稳定、站点语音提示清楚、段间过渡自然、Quest 2 端运行稳定。BGM 不作为项目成败的核心标准。

当前实现决策：正式音频素材只制作三站 BGM 和四段韩语语音播报，不再制作火车底噪、风声、鸟鸣、瀑布声、夜风等环境音素材。

**BGM 方向：**

| 站点 | 音乐方向 |
|---|---|
| 金色乡村站 | 温暖弦乐，欧洲乡村风格，可加入钢琴或手风琴点缀 |
| 峡湾观景站 | 宽广的管弦乐或氛围乐，突出山水尺度感 |
| 极光花田站 | 空灵安静的氛围乐，可加入轻柔合成器或冥想钢琴 |

**音频技术细节：**

- 使用 Audacity 进行降噪、音量统一、淡入淡出处理。
- Unity 中使用 AudioSource 管理 BGM 和语音提示。
- 播放语音提示时降低 BGM 音量，保证提示内容清晰可懂。
- 段间转场时避免突兀切换，音频与视频节奏保持一致。

### 6.3 基础脚本模块设计

本项目虽然以低交互、观看式体验为主，但作为技术类课程项目，仍需要使用基础 C# 脚本完成播放流程控制、站点提示、过渡效果和必要的手柄输入。脚本目标是简单、明确、可完成，不追求复杂交互系统。

| 脚本模块 | 计划功能 | 实现难度 | 设计意义 |
|---|---|---|---|
| `JourneySequenceController` | 控制三段视频按顺序播放，管理当前站点状态 | 简单 | 让项目具有清晰的流程控制，而不是手动播放素材 |
| `StationAnnouncementController` | 控制开场、到站、下一站和终点语音提示 | 简单 | 回应 mentoring 中“需要知道当前在哪”的核心反馈 |
| `FadeTransitionController` | 控制段间黑场或暗场淡入淡出 | 简单到中等 | 增强视频之间的承接性，减少突兀切换 |
| `AudioMixController` | 控制 BGM 和语音提示之间的音量关系 | 简单 | 保证语音提示清晰，同时保留沉浸氛围 |
| `ComfortSettings` | 固定坐姿视角，限制不必要移动和旋转 | 简单 | 服务老年用户舒适性和晕动风险控制 |
| `VRInputController` | 读取 VR 手柄按钮输入，触发开始、重新居中、暂停继续和跳到下一站 | 简单 | 保留 demo 演示所需的基本手柄交互，但不增加复杂操作 |

优先实现顺序为：`JourneySequenceController`、`StationAnnouncementController`、`FadeTransitionController`、`VRInputController`。在时间允许的情况下，再加入 `AudioMixController` 和 `ComfortSettings`。
### 6.4 Demo 演示中的手柄交互设计

由于项目最终以 demo 演示为主，不需要制作完整首页、路线选择界面或复杂动画菜单。但为了体现 VR 项目的基本可控性，并方便课堂展示与调试，手柄交互仍然保留以下功能：

| 手柄功能 | 用途 | 面向对象 |
|---|---|---|
| 开始体验 | 从待机状态进入三站旅程播放流程 | 用户或演示者 |
| 重新居中视角 | 将用户视角重新对准前方观景窗 | 用户或演示者 |
| 暂停 / 继续 | 演示讲解或测试时临时暂停与恢复 | 演示者 |
| 跳到下一站 | 快速展示后续主题，减少课堂演示等待时间 | 演示者或开发测试 |

这些手柄功能不与视觉过渡脚本重合。`VRInputController` 只负责读取按钮输入，并调用其他脚本的公开方法；具体播放逻辑仍由 `JourneySequenceController` 管理，渐变效果仍由 `FadeTransitionController` 管理，视角重置仍由坐姿视角相关脚本管理。

```text
VRInputController
├─ 开始体验 → JourneySequenceController.StartJourney()
├─ 暂停 / 继续 → JourneySequenceController.TogglePause()
├─ 跳到下一站 → JourneySequenceController.SkipToNextStation()
└─ 重新居中 → SeatedViewInitializer.RecenterView()
```

这种结构可以避免脚本职责混乱：手柄脚本只负责“输入”，旅程脚本负责“流程”，渐变脚本负责“视觉过渡”，坐姿视角脚本负责“视角基准”。

### 渲染管线与 XR 框架选择理由

当前项目从旧 Unity 版本重建到 Unity 6000.3.16f1 LTS 后，不再继续采用 Built-in Render Pipeline。原因是 Unity 官方已经将新项目方向集中到 URP，Built-in Render Pipeline 虽然仍可使用，但更适合维护旧项目，不适合作为新版 Unity 6 新建 VR 项目的首选方案。

本项目最终选择 URP + XR Interaction Toolkit + OpenXR，理由如下：

- URP 是 Unity 6 新项目更推荐的通用渲染管线，适合移动端、XR 和跨平台项目。
- 项目目标设备是 Meta Quest 2，需要优先考虑移动 VR 性能，URP 可通过关闭高成本效果来获得稳定帧率。
- XR Interaction Toolkit + OpenXR 能满足本项目的基础 VR 手柄输入、XR Origin、头显追踪和简单交互需求。
- 本项目不需要复杂 Meta 平台专属功能，因此不以完整 Meta SDK 或 Oculus Integration 作为主框架。
- 如后期需要 Meta Quest 特定扩展功能，可在 OpenXR 基础上补充 Unity Meta OpenXR，而不改变整体架构。

### Quest 2 的 URP 性能设置原则

URP 需要按移动 VR 项目进行轻量化配置，不能直接使用高质量默认设置。当前建议如下：

| 设置项 | 建议 |
|---|---|
| Graphics API | Vulkan 优先 |
| URP Renderer | Forward Renderer，避免使用 Forward+ |
| HDR | 关闭 |
| Post-processing | 关闭或只保留最低限度效果 |
| MSAA | 2x 优先，性能允许时再考虑 4x |
| Render Scale | 从 1.0 开始，根据 Quest 2 实机帧率调整 |
| Opaque Texture | 非必要关闭 |
| Depth Texture | 非必要关闭 |
| 实时阴影 | 尽量少用或关闭 |
| 车厢模型 | 优先基础几何体和简单材质 |
| 视频规格 | 先使用 1600x900 或 1920x1080 测试，依据实机性能调整 |

该方案与项目设计理念不冲突。项目核心仍然是低交互、稳定观看、三站视频播放和到站提示；URP 只是为了让 Unity 6 新项目拥有更合理的长期兼容性和移动 VR 支持。

### 新项目重建策略
由于旧项目在新版 Unity LTS 中出现材质异常，当前开发不再继续沿用旧项目资源状态，而是采用新项目重建策略：

1. 在新版 Unity LTS 中创建干净项目。
2. 使用 URP 作为渲染管线，并为 Quest 2 进行轻量化设置。
3. 重新配置 XR Interaction Toolkit、OpenXR 和 Android 构建环境。
4. 先搭建前端二层观景空间、正前方大窗和基础车厢结构。
5. 再逐步导入或重建必要材质、模型、视频和音频资源。
6. 加入基础 C# 脚本，用于管理旅程顺序、站点提示、过渡效果和 demo 手柄控制。
7. 对旧项目中可复用的设计经验进行保留，但不直接依赖旧项目的场景和材质配置。

## 11. 风险与应对策略

| 风险项 | 应对策略 |
|---|---|
| 旧项目升级后材质或设置异常 | 不继续依赖旧项目，采用新版 Unity LTS 新项目重建，并改用 URP 重新建立材质体系 |

| Seedance 2.0 视频生成质量不稳定 | 每站生成多个候选片段，筛选稳定素材后再剪辑成站点视频 |
| 视频之间切换突兀 | 使用到站语音提示、短暂停顿和淡入淡出过渡，并由 Unity 脚本控制切换时机 |
| 老年用户不知道当前处于哪一站 | 将三段视频设计为三站结构，并加入清晰语音提示 |
| AI 生成 BGM 风格不匹配主题 | BGM 作为辅助元素保留，必要时简化或使用可授权音乐替代 |
| 语音提示被 BGM 遮盖 | 播放语音时降低 BGM 音量，保证提示优先级 |
| 老年用户晕动症 | 固定坐姿视角、稳定速度、柔和转场，避免快速运动和旋转；必要时通过手柄重新居中视角 |
| Quest 2 性能瓶颈 | 使用 URP 轻量化配置，关闭 HDR 和不必要后处理，优先基础几何体和简单材质，控制模型复杂度、贴图分辨率和视频规格 |
| 高质量模型替换后尺寸不一致 | 占位阶段记录关键 Transform 数值，替换时按比例对齐 |

## 12. 结论

本项目以沉浸式火车观光体验为核心，通过金色乡村站、峡湾观景站和极光花田站三段视觉旅程，为身体不便的老年用户提供现实中难以抵达的世界体验。

根据课程合作老年人福利中心 mentoring 的反馈，项目不再只是连续播放三段风景视频，而是调整为具有站点结构、到站语音提示和段间过渡的完整旅程。这样可以帮助老年用户明确知道自己当前的位置，也让三段视频之间形成更自然的承接关系。

载体上采用列车前端二层全景观光车厢概念，既保留“火车之旅”的项目身份，又通过正前方观景视角强化列车前进方向。铁轨可以作为窗外视频中的方向感元素存在，Unity 负责稳定呈现基础车厢空间，AI 视频负责窗外前向推进的景观内容，基础 C# 脚本负责旅程顺序、站点提示、过渡控制和 demo 手柄输入。

在开发策略上，项目已从旧 Unity 项目迁移为新版 Unity LTS 新项目重建。渲染管线采用 URP，XR 框架采用 XR Interaction Toolkit + OpenXR。这样可以避免旧项目升级带来的材质异常和隐藏兼容问题，也更适合 Unity 6、Meta Quest 2、AI 视频素材和基础 VR 手柄交互的后续开发。

最终目标是：用 VR 技术弥补老年用户的身体局限，让他们以安全、舒适、有美感且容易理解的方式看见更广阔的世界。
