## 2. 项目定位

项目名称：`VR Train Journey Experience`

这是一个面向老年用户的固定坐姿 VR 课程 Demo。用户佩戴 Meta Quest 2 后，会坐在列车前端二层的全景观光车厢中，通过正前方的大型观景窗观看三段列车旅行风景。

项目重点不是复杂操作，而是：

- 舒适、稳定、容易理解的观看体验。
- 明确的列车前进方向。
- 适合老年用户的低操作负担。
- 简单但完整的三站式旅程流程。
- 在 Meta Quest 2 上稳定运行。

体验中的用户身份是乘客，不是司机。不要创建驾驶室、方向盘、控制台、仪表盘或复杂机械结构。

## 3. 核心视觉设计

### 3.1 空间设定

用户位于列车最前端的二层观光区域，坐在座椅上，主要朝向正前方。空间需要让用户自然理解：

- 自己正坐在列车内部。
- 列车正在向前行驶。
- 最值得观看的区域是前方大窗。
- 侧面环境只负责增强车厢感，不抢夺注意力。

### 3.2 观景逻辑

本项目采用前向观景，不采用传统侧窗观景作为主要体验。

- 正前方大窗是场景视觉中心。
- 窗外内容未来会通过独立视频播放系统呈现。
- 视频可以出现铁轨，因为铁轨有助于表达列车前进方向。
- 不要用复杂车头结构遮挡正前方视野。
- 不要让侧窗成为比前窗更强的视觉焦点。

### 3.3 内饰方向

车厢风格应当舒适、简洁、温暖，具有轻度观光列车氛围。优先使用：

- 暖色木纹或暖灰色地板。
- 低饱和度墙面。
- 简单金属窗框。
- 柔和暖色灯带。
- 少量装饰画或简洁软装。

避免：

- 过度现代化的科幻风格。
- 高反射镜面材质。
- 大量复杂装饰。
- 密集小物件。
- 强烈闪烁、动态灯光和刺眼高亮。

## 4. 完整体验流程

项目最终体验结构如下：

```text
坐姿初始化与前向校准
↓
开场语音提示
↓
第一站：金色乡村站
↓
柔和淡出、到站提示、短暂停顿、淡入
↓
第二站：峡湾观景站
↓
柔和淡出、到站提示、短暂停顿、淡入
↓
第三站：极光花田站
↓
终点语音提示与体验结束
```

三站的情绪方向：

| 站点 | 主题 | 情绪 |
| --- | --- | --- |
| 金色乡村站 | 欧洲乡村午后 | 温暖、熟悉 |
| 峡湾观景站 | 挪威峡湾铁路 | 开阔、震撼但稳定 |
| 极光花田站 | 极光下的花田 | 安静、平和 |

当前搭建车厢时，只需为未来的视频、音频和脚本保留清晰结构。不要提前实现这些系统。

## 6. Quest 2 移动 VR 约束

这是 Meta Quest 2 独立运行项目，不是 PC VR 项目。场景搭建和资源导入时必须主动控制成本。

### 6.1 当前 URP 基线

以下设置已经确定，不要擅自修改：

| 设置 | 当前值 |
| --- | --- |
| HDR | 关闭 |
| MSAA | `2x` |
| Render Scale | `0.8` |
| Depth Texture | 关闭 |
| Opaque Texture | 关闭 |
| Rendering Path | `Forward` |
| Depth Priming | `Disabled` |
| 移动端后处理 | 关闭 |
| 主光源实时阴影 | 关闭 |
| 附加光源 | `Per Vertex` |
| 附加光源实时阴影 | 关闭 |
| 反射探针高级能力 | 关闭 |

### 6.2 场景资源预算原则

执行时遵循以下规则：

- 车厢主体优先使用少量基础几何体。
- 重复元素优先复用同一个 Prefab 和同一套材质。
- 座椅使用一套低模资源，通过 Prefab 复用。
- 不为每个重复对象创建独立材质实例。
- 材质尽量合并复用，避免大量 Draw Call。
- 当前阶段纹理优先使用 `1024x1024` 或更低分辨率。
- 只有前方视觉重点资源确有必要时，才考虑 `2048x2048`。
- 不导入 `4K` 或更高分辨率纹理作为默认方案。
- 导入纹理时检查 Android 平台压缩设置，优先使用适合 Quest 2 的 `ASTC`。
- 基础灯光优先使用烘焙思路或简单无阴影灯光。
- 不创建实时阴影、反射镜面、透明层叠或复杂 Shader，除非用户明确批准。
- 不启用后处理、SSAO、Bloom 或其他高成本效果。

如果导入模型或纹理明显超出轻量 Demo 需求，请先汇报问题和建议，不要直接批量使用。

## 8. 当前最高优先级：车厢场景搭建

当前只负责搭建车厢内部空间和坐姿观察体验。此阶段优先级最高。

### 8.1 当前负责范围

- 车厢内部基础空间比例。
- 前方大型观景窗和窗框。
- 地板、侧墙、天花板。
- 座椅导入、缩放、朝向、Prefab 化和合理排列。
- 简化车门。
- 简化行李架。
- 少量装饰物。
- 简单 URP 材质和纹理。
- 基础无阴影灯光。
- 玩家固定坐姿位置和主要观察方向。
- 模型面数、材质数量、纹理尺寸和重复对象数量控制。

### 8.2 当前明确不处理

- 窗外视频导入和播放。
- `VideoPlayer` 设置。
- 三站视频切换。
- 音频、语音和 BGM。
- 手柄按钮交互。
- 交互脚本。
- 最终性能测试。
- 复杂 UI。
- XR 配置重做。
- 大量装饰资源搜索和导入。

### 8.3 推荐搭建顺序

每次只执行一项，完成后等待确认：

1. 审计当前场景 Hierarchy，不修改任何对象。
2. 建立车厢白模根节点和基础目录。
3. 使用基础几何体搭建地板、墙体、天花板。
4. 建立前方大窗和窗框，确认前向视野。
5. 放置单个座椅样例，确认比例、坐高和朝向。
6. 将确认后的座椅制作成 Prefab，再进行有限数量复制。
7. 添加侧窗、简化车门和简化行李架。
8. 创建少量可复用 URP 材质。
9. 添加简单无阴影灯光。
10. 从玩家坐姿视角检查空间比例和主要观察方向。
11. 汇总模型、材质、纹理和灯光数量，等待下一阶段决策。

## 9. 白模阶段规范

白模阶段的目标是确认空间，不是装饰。

### 9.1 坐标约定

- Unity 单位按米理解：`1 Unity unit = 1 meter`。
- 默认将列车前进方向设为世界坐标 `+Z`。
- 用户主要朝向也设为 `+Z`。
- 将整个车厢结构放在一个清晰的根节点下，例如 `TrainCar_Interior`.
- 车厢主体和 XR Origin 分开管理。
- 不要将车厢结构作为 XR Origin 的子对象。

### 9.2 初始比例建议

以下数值是白模起点，不是不可修改的最终值：

| 项目 | 建议起点 |
| --- | --- |
| 车厢内部宽度 | 约 `3.0 m` |
| 当前可见区域长度 | 约 `5.0 - 7.0 m` |
| 车厢内部高度 | 约 `2.3 - 2.6 m` |
| 坐姿眼高 | 约 `1.15 - 1.30 m` |
| 前方大窗宽度 | 约 `2.4 - 2.8 m` |
| 前方大窗高度 | 约 `1.4 - 1.8 m` |

判断标准：

- 用户坐下后，正前方大窗应自然占据主要视野。
- 窗框存在但不应遮挡太多视野。
- 用户转头时可以看到侧墙、少量侧窗、邻近座椅和车厢结构。
- 空间不能像驾驶室，也不能像空旷展厅。
- 不要一次布置过多座椅。先验证单椅，再逐步复制。

### 9.3 Hierarchy 建议

```text
TrainCar_Interior
├── Architecture
│   ├── Floor
│   ├── Ceiling
│   ├── SideWalls
│   ├── FrontWindow
│   ├── SideWindows
│   └── Doors
├── Furniture
│   ├── Seats
│   └── LuggageRacks
├── Decoration
└── Lighting
```

这只是推荐结构。执行前先检查当前 Hierarchy，避免与已有对象命名冲突。

当前计划使用一套低模座椅资源：

```text

Armchair_Normal.png
Armchair_Metallic.png
Armchair_Roughness.png

```

推荐目标目录：

```text
Assets/Art/Models/Armchair/
```

导入后执行顺序：

2. 检查贴图分辨率和 Android 导入设置。
3. 创建一个适用于 URP 的共享材质。

5. 注意 Unity URP Lit 材质与资源中的 `Roughness` 贴图工作流不同。不要未经说明直接错误连接；如需使用，应先说明转换或处理方案。
6. `AO` 贴图仅在确有收益且连接方式明确时使用。
7. 将经过确认的座椅制作成 Prefab。
8. 未确认前不要批量复制。

## 11. 玩家坐姿与 XR Origin 规则

当前体验为固定坐姿 VR：

- 玩家坐在座位上观看前方。
- 玩家可以自然转头、抬头和低头。
- 不要锁死头显旋转。
- 不提供自由移动或传送。
- 不要擅自删除或重建已有 `XR Origin (VR)`。
- 调整玩家初始位置前，先汇报准备修改的对象和理由。
- 坐姿校准和重新居中逻辑属于后续脚本阶段，当前只验证空间中的合理初始位置。

验收时应从 Main Camera 的实际坐姿观察角度检查：

- 前窗是否是第一视觉重点。
- 窗框是否遮挡过多。
- 座椅高度是否自然。
- 用户是否感觉位于乘客空间而不是驾驶空间。
- 转头后是否有足够车厢内饰提供空间参照。

## 13. Unity AI 执行协议

每次收到任务后，严格遵循：

1. 先检查当前场景、选中对象和相关资产。
2. 用简短列表说明准备新增、修改或删除哪些对象。
3. 说明为什么这样做。
4. 等待用户确认。
5. 一次只执行一个小步骤。
6. 执行后汇报结果，不自动继续下一步。

每次执行后的汇报格式：

```text
已完成：
- ...

新增或修改的对象：
- 对象名称：
  - Parent：
  - Position：
  - Rotation：
  - Scale：

新增或修改的资产：
- 路径：
- 用途：

性能影响：
- 模型数量：
- 材质数量：
- 纹理尺寸：
- 灯光数量和阴影状态：

需要用户确认：
- ...

下一步建议：
- ...
```

遇到以下情况必须暂停并询问用户：

- 想修改 XR Origin、Project Settings、URP Asset 或 OpenXR 设置。
- 想删除现有对象或资产。
- 想导入新的第三方资源。
- 想批量生成大量对象。
- 发现贴图尺寸过大、材质数量异常或模型明显过重。
- 文档要求与当前场景状态冲突。
- 不确定用户希望采用哪一种方案。
